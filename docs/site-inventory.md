# サイト管理の棚卸し（2026-11-13 時点）

GitHub・Cloudflare Pages・Pages CMS・公開サイトを、設定を変更せずに読み取りだけで確認した結果。

## 1. 運用基盤

| 項目 | 現状 |
|---|---|
| リポジトリ | `SI-Monxy/rinyaku-website`（本番ブランチ `main`） |
| 公開 URL | https://rinyaku-website.pages.dev （独自ドメインは未設定） |
| 検索エンジン | `robots.txt` で全拒否（検証中のため） |
| Cloudflare Pages | GitHub と連携済み。`main` への push で本番が自動デプロイされる |
| ビルド設定 | `npm run build` → `dist`。ビルドシステムはバージョン 3。環境変数・デプロイフック・通知はいずれも未設定 |
| プレビューデプロイ | `main` 以外の全ブランチで自動作成される。URL を知っていれば誰でも閲覧できる（アクセス制限なし） |
| GitHub Actions | push と PR でビルドを確認（Cloudflare とは別に実行） |
| Pages CMS | リポジトリ連携済み。編集すると `main` に直接コミットされる。ブランチは切り替えられる |
| CMS の編集者 | オーナー（SI-Monxy）のみ。招待済みの共同編集者はいない |
| CMS 経由の更新実績 | 2026-09-17 に2件（行事 2013年度の削除、お知らせの編集）。どちらも本番に反映済み |

ビルドに失敗した場合、本番は直前に成功した状態のまま残る。ただし通知を設定していないため、CMS で編集した人は失敗に気づけない。

## 3. 不具合・リスク

| # | 内容 | 影響 |
|---|---|---|
| 1 | 移行した本文にある画像リンク `../img/xxx.jpg` が 354 か所（16ファイル）壊れている | 行事などで画像をクリックすると、拡大画像ではなくトップページが表示される |
| 2 | 業績の本文に旧サイトへの相対リンク `../category6/entryXX.html` が 17 か所ある | クリックするとトップページが表示される |
| 3 | 404 ページがない | 存在しない URL や削除したページ（例：`/events/2013/`）でも、トップページがステータス 200 で表示される |
| 4 | 行事の「概要」「カバー画像パス」は CMS では任意入力だが、ビルドでは必須 | 空欄で保存するとビルドが失敗し、本番が更新されない（通知もない） |
| 5 | 行事のカバー画像は文字入力でパスを書く | 画像を選んで指定できない。パスを書き間違えると画像が表示されない |
| 6 | CMS で保存すると frontmatter の書式（引用符・項目の順番）が変わる | 表示には影響しない。業績など長い本文では、どこまで変わるか未確認 |
| 7 | CMS の編集者がオーナーだけ | 研究室の他のメンバーが更新するには招待が必要 |
| 8 | 手元の `main` が GitHub より2コミット遅れている | 作業ブランチを最新の `main` から切り直す必要がある |

## 4. 確認方法

- GitHub：`gh` でコミット履歴とチェック結果（Cloudflare のデプロイ結果）を確認
- Cloudflare：ダッシュボードの「デプロイ」「設定」「カスタムドメイン」を確認
- Pages CMS：メニュー、お知らせと行事の一覧と編集フォーム、Collaborators を確認（保存はしていない）
- 公開サイト：`curl` で各ページ、存在しない URL、画像リンクを確認
